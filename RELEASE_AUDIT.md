# MISPFuse 2.1.0 release checklist

Last reviewed: 24 July 2026

MISPFuse is still a release candidate. The source tree is prepared for a final
build, but publication depends on tests that must run in the publisher's Splunk
and MISP environments.

## Identity

- Splunkbase title: `MISPFuse`
- Package ID and root directory: `mispfuse`
- Listing type: App
- Version: `2.1.0`
- Build: generated by UCC as a positive Unix timestamp during the final build

No public Splunkbase listing with the exact title MISPFuse was found during the
review. The authenticated submission form is the final check for title and
package-ID availability. MISP42 provides overlapping MISP workflows, so the
listing should describe MISPFuse as an outbound, template-driven publisher
rather than a general MISP integration.

## Packaging

The runtime requirements are exact-version and hash locked:

- defusedxml 0.7.1
- PySocks 1.7.1
- sortedcontainers 2.4.0
- solnlib 7.0.0
- splunk-sdk 3.0.0
- splunktaucclib 8.2.0
- urllib3 1.26.20

PyMISP and requests are not included. The post-build script checks the Python
3.13 declarations, custom account handler, app identity, dependency lock, and
absence of native binary files.

## Source checks completed

- `globalConfig.json` and `app.manifest` parse successfully.
- All Python files compile with Python 3.13.
- All 25 unit tests pass.
- The source tree contains no `.so`, `.pyd`, `.dll`, or `.dylib` files.
- Icons are present in the required sizes.
- Runtime requirements use exact versions and hashes.

## Required before upload

1. Build from a clean Python 3.13 virtual environment with UCC 6.5.3.
2. Run `make release` and keep the AppInspect report.
3. Test account create and edit against a real MISP 2.5 server.
4. Run the four README command examples against a non-production MISP account.
5. Test the alert action with `sendalert` and with a scheduled alert.
6. Verify tags, distribution, `to_ids`, analysis state, and publication state in MISP.
7. Install and upgrade-test the package on Splunk Enterprise 10.2 or later.
8. Test every operating system and deployment type claimed in Splunkbase.
9. Replace the placeholder publisher details with real support and repository information.
10. Confirm the title and package ID in the authenticated Splunkbase form.
11. Complete Cloud vetting before claiming Splunk Cloud compatibility.
